On the About page (and anywhere prose uses a straight apostrophe), the apostrophe in e.g. "B612's unusual character" (docs/specimen/planetaire-mono-specimen.typ:138) renders as a thin/spindly mark, not Hack's substantial vertical apostrophe.

DIAGNOSIS: The source uses a straight ASCII apostrophe U+0027 (0x27) and smartquotes is globally disabled (#set smartquote(enabled: false) at planetaire-mono-specimen.typ:744 and content.typ:173). The curly apostrophe U+2019 renders CORRECTLY in the same PDF (e.g. 'Ryan McIntyre\xe2\x80\x99s' in the credits). pdffonts on the PDF shows DejaVuSansMono + DejaVuSansMono-Oblique embedded as fallbacks. So U+0027 is being served by the DejaVu fallback (spindly) while U+2019 comes from Planetaire/Hack (correct). Apostrophe codepoints are OUTSIDE PLANETAIRE_LETTER_RANGES (config.py:51-64, letters/digits only), so the font's apostrophe should be Hack's -- confirm whether U+0027 actually survives into the built Planetaire Mono Extended cmap.

FIX (systematically, wherever the origin is):
- Confirm the built font cmap for U+0027 (and straight quote/backtick); if missing/dropped, find where in merge/subset/normalize and restore from Hack so no fallback occurs.
- In prose prefer proper typographic apostrophes/quotes (U+2019/U+201C/U+201D) to match README, which renders correctly; keep smartquotes off so code stays literal. Audit all specimen + doc prose for stray straight apostrophes used as apostrophes.
- Optionally set Typst text fallback to a Planetaire/Hack face (or disable fallback) so future gaps surface instead of silently using DejaVu.
Files: docs/specimen/planetaire-mono-specimen.typ, content.typ, src/planetaire/config.py, merge/subset/normalize ops.

## Notes

RESOLVED. U+0027 is present and intact in the built font (Hack's apostrophe; apostrophes are outside PLANETAIRE_LETTER_RANGES so kept from Hack verbatim). The 'spindly' apostrophe in the committed PDF was a STALE render: a fresh 'planetaire build specimen' renders U+0027 from Planetaire (verified -- an isolated render of "B612's" embeds only PlanetaireMonoExtended and the apostrophe is substantial). The DejaVu seen via pdffonts was NOT the apostrophe; it was code/raw blocks defaulting to Typst's DejaVu -- fixed and QA'd separately. Action at commit: ship the freshly rebuilt specimen PDF.
