The committed B612Mono-ExtraBold{,Italic}.ttf are NOT outputs of our pipeline. Metadata (2026-06-09): version "1.010; ttfautohint (v1.8.4)", uniqueID "Version 1.010;;B612MonoLigaNerdFont-Bold;2024;FL830" — an old hand-built artifact descending from a "B612 Mono Liga Nerd Font" Bold, a DIFFERENT lineage than the clean Airbus B612 Bold the repo vendors. By contrast Medium/SemiBold carry uniqueID "Airbus: B612 Mono Regular: Version1.008", i.e. genuine embolden_font output from Regular.

The build never regenerates ExtraBold: _ensure_generated_weights skips when the file exists, and the file is committed, so every build reuses the old artifact. They were also committed in the first repo commit, before the embolden pipeline existed.

Fix: remove the vendored ExtraBold pair and regenerate from B612Mono-Bold{,Italic}.ttf via embolden_font (change_amount=30, target_weight=800) so all synthetic weights share one clean, reproducible Airbus 1.008 lineage; refresh SHA256SUMS and golden; re-validate metrics/outlines. Requires FontForge (absent in CI sandbox).

Also fix fonts/source/README.md provenance drift: it omits SemiBold (generated from Regular, added later) and wrongly states ExtraBold is "generated by the Planetaire build pipeline" (true only after this regen). Files: recipes/planetaire_mono.py (_EXTRABOLD_FROM_BOLD), ops/embolden.py, fonts/source/b612/*, fonts/source/SHA256SUMS, fonts/source/README.md.
